# ADR 0002: The schema holds pseudonymous subject codes only, never PHI

- **Status:** accepted
- **Date:** 2026-09-19

## Context

ECG data is health data. In a real deployment, a recording linked to a name, medical record
number or date of birth is protected health information (PHI) under HIPAA, and personal data
of a special category under GDPR. PulseStore is a portfolio project that uses the public,
de-identified MIT-BIH database, but the schema should be the one you would defend in a real
system.

## Decision

- Subjects are identified only by an opaque `subject_code` (`MITBIH-100`, for example). There
  are no columns for names, dates of birth, addresses or medical record numbers.
- The database enforces the format with a `CHECK` constraint (`^[A-Z0-9-]{3,32}$`), and the API
  enforces the same pattern before the query is sent. A value such as `Juan Perez` is rejected
  at both layers: spaces and lowercase letters cannot pass.
- The mapping from subject code to a real person, if it existed, would live in a separate
  system with its own access control, outside this service.

## Consequences

- **Good:** a leak of this database exposes signals and pseudonymous codes, not identities.
  Re-identification from an ECG alone is possible in principle, so this lowers the risk but does
  not remove it.
- **Good:** the rule is enforced twice. An API bug alone cannot write a name into the table.
- **Bad:** the format check is a heuristic. A code like `JUAN-PEREZ` would pass. The control is
  that codes are generated by the ingest side, not typed by people.
- **Scope:** this project stores only public data. No data from any employer, and nothing
  resembling process data, part numbers or device history records, ever goes into this
  repository.
